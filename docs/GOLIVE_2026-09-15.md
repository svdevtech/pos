**Migration ที่จะรันอัตโนมัติตอน API ขึ้น:** `0013` → `0018`
ทั้งหมดเป็น **CREATE TABLE ใหม่** หรือ **ADD COLUMN ... DEFAULT** เท่านั้น ไม่มีการลบ/แก้ข้อมูลเดิม ตารางของร้านค้าเดิม (`sales`, `products`, `members`, …) ถูกแตะแค่ 3 จุดคือเพิ่มคอลัมน์ `sales.order_id` (0014), `orders.sale_id` (0017) และคอลัมน์โปรโมชันบน `order_items` (0018)

## 3. ขั้นตอน deploy

รันจาก **Git Bash บนเครื่อง dev** ที่ `D:\workspace\pos` (branch `main`)

### 3.1 สำรองฐานข้อมูลก่อน (บังคับ)

```bash
ssh ubuntu-server 'bash /data/pos/src/deploy/tee-dev/backup.sh && ls -lh /data/pos/backups | tail -3'
```

ต้องได้ไฟล์ `pos-YYYYMMDD-HHMMSS.dump.gz` ใหม่ **ถ้าคำสั่งนี้ล้ม ห้าม deploy ต่อ**

### 3.2 deploy

```bash
cd /d/workspace/pos
git branch --show-current                   # ต้องเป็น main
git status --short                          # ต้องว่าง
git rev-parse --short HEAD                  # จดไว้ = เวอร์ชันที่จะขึ้น
bash deploy/tee-dev/deploy.sh
```

สคริปต์จะ tar โค้ดขึ้น `/data/pos/src` แล้ว `docker compose up -d --build` (build เว็บ+api ใหม่ ใช้เวลา ~4–8 นาที ครั้งนี้นานกว่าปกติเพราะมี stage `fnb3d` เพิ่ม) จบแล้วสคริปต์จะ `curl /health` ให้เอง

### 3.3 ตรวจหลัง deploy

```bash
# 1. เวอร์ชันและ container
ssh ubuntu-server 'cat /data/pos/src/VERSION; cd /data/pos/src/deploy && docker compose --env-file /data/pos/.env ps'

# 2. migration ต้องขึ้น version 18 และ dirty=false
ssh ubuntu-server 'cd /data/pos/src/deploy && docker compose --env-file /data/pos/.env logs api --tail 40 | grep -i "migrations applied"'

# 3. สุขภาพ API
curl -fsS https://t-pos.tdev2022.com/api/v1/health; echo

# 4. ข้อมูลร้านเดิมยังครบ (ต้องได้ตัวเลขเท่าเดิม ไม่ใช่ 0)
ssh ubuntu-server "cd /data/pos/src/deploy && docker compose --env-file /data/pos/.env exec -T postgres psql -U pos -d pos -c \\"SELECT s.code, count(*) AS bills FROM sales x JOIN stores s ON s.id=x.store_id GROUP BY s.code ORDER BY s.code;\\""
```

เกณฑ์ผ่าน: `VERSION` ตรงกับค่าที่จดไว้ในข้อ 3.2 · api/web/postgres = Up (healthy) · `migrations applied version=18 dirty=false` · health = `{"status":"ok"}` · จำนวนบิล BBR ≈ 466,2xx และ KAEN ≈ ตามที่เคยนำเข้า

### 3.4 ตรวจด้วยตา (บนเบราว์เซอร์)

1. เปิด `https://t-pos.tdev2022.com` → เห็น **หน้าล็อกอินใหม่** (ออโรราเคลื่อนไหว การ์ดกระจก)
2. ล็อกอิน `BBR` → แดชบอร์ดขึ้นยอดเดิมถูกต้อง เปิดหน้า **ขายหน้าร้าน** แล้วสแกน/ค้นสินค้า 1 รายการ **แล้วกดยกเลิกตะกร้า** (ไม่ต้องขายจริง)
3. เมนู **คู่มือ** → เห็น 3 แท็บ และภาพในคู่มือโหลดขึ้น
4. ล็อกอิน `KAEN` → แดชบอร์ดปกติ
5. (ไม่บังคับ) เปิด `/fnb/order` เพื่อดูว่าโมดูลร้านอาหารขึ้น — ร้านค้าปลีกจะยังไม่มีเมนู/โต๊ะ ถือว่าปกติ

## 4. ถ้าพลาด — rollback

```bash
cd /d/workspace/pos
git checkout 56f90af          # เวอร์ชันที่รันอยู่เดิม
bash deploy/tee-dev/deploy.sh
git checkout main             # กลับมา branch เดิมบนเครื่อง dev
```

> migration 0013–0018 เป็นการ **เพิ่ม** ตาราง/คอลัมน์เท่านั้น โค้ดเก่าไม่ได้ใช้ของใหม่ จึงย้อนโค้ดได้โดยไม่ต้องกู้ฐานข้อมูล
