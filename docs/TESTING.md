# การทดสอบระบบ (Testing)

ระบบมีการทดสอบ 4 ชั้น เรียงจากเร็ว/แคบ ไปช้า/กว้าง

| ชั้น | อยู่ที่ | ครอบคลุม | คำสั่ง |
|---|---|---|---|
| Unit (Go) | `backend/internal/**/*_test.go` | คณิตศาสตร์การขาย ปันผล ต้นทุนเฉลี่ย การแปลงหน่วย วันที่ พ.ศ. ข้อความ error สองภาษา | `cd backend && go test ./...` |
| Unit (frontend) | `frontend/i18n`, `npx tsc` | คีย์ภาษาไทย/อังกฤษตรงกัน, ชนิดข้อมูล | `cd frontend && npm run i18n:check && npx tsc --noEmit && npm run lint` |
| E2E จำลอง API | `frontend/tests/e2e/*.spec.ts` | หน้าจอจริงในเบราว์เซอร์ โดย mock `/api/v1/**` — ใช้ตรวจ logic ของ UI, กรณีขอบ และการดาวน์โหลดไฟล์ | `cd frontend && npx playwright test` |
| **ทดสอบทั้งระบบบนเว็บจริง** | `frontend/tests/live/full-system.mjs` | ล็อกอินจริง ขายจริง ตัดสต็อกจริง สำรองข้อมูลจริง บนเซิร์ฟเวอร์ที่ deploy แล้ว | ดูด้านล่าง |
| **ทดสอบหลายร้าน (multi-tenant)** | `frontend/tests/live/multi-store.mjs` | สร้างร้านที่ 2 จากหน้าผู้ดูแล ใช้งานจริง แล้วพิสูจน์ว่าข้อมูลสองร้านไม่ปนกัน | ดูด้านล่าง |

## ทดสอบทั้งระบบบนเว็บจริง

```bash
cd frontend
node tests/live/full-system.mjs                          # ค่าเริ่มต้น https://t-pos.tdev2022.com
BASE=http://100.122.174.19:3010 node tests/live/full-system.mjs   # ตรงเข้าเซิร์ฟเวอร์ (เร็วกว่า ไม่ผ่าน tunnel)
node tests/live/cleanup.mjs                              # เก็บกวาดข้อมูลทดสอบหลังรัน
```

- ใช้ Playwright เปิด Chromium จริง กดปุ่มเหมือนผู้ใช้ ทั้งจอคอมพิวเตอร์และจอมือถือ (Pixel 7)
- ข้อมูลที่สร้างขึ้นทุกชิ้นมีรหัสรอบทดสอบ `E2E-<วันเวลา>` เพื่อให้แยกออกและลบได้
- ต้องมีบัญชีเจ้าของร้าน (ค่าเริ่มต้น `owner`) ตั้งค่าได้ด้วย `STORE`, `E2E_USER`, `E2E_PASS`
- ผลลัพธ์ถูกเขียนไว้ที่ `tests/live/report.json` และภาพหน้าจอของขั้นที่ล้มเหลวอยู่ใน `tests/live/shots/`
- ระหว่างรันจะมีการขาย ยกเลิกบิล ปรับสต็อก และสร้างไฟล์สำรองข้อมูลจริง **อย่ารันบนร้านที่ใช้งานจริงในเวลาทำการ**

`2026-09-03` เวอร์ชัน `6c2b40f` — **ผ่าน 39 / ล้มเหลว 0** (รวมผู้ช่วย AI ที่เปิดใช้งานจริงแล้ว)

ข้อบกพร่องที่พบจากการทดสอบรอบนี้และแก้แล้ว

| # | อาการ | สาเหตุ | การแก้ไข |
|---|---|---|---|
| 1 | เมนู "ผู้ช่วย AI" กดแล้วขึ้น 404 และทุกหน้าจะยิงโหลด `/ai` ค้างไว้เป็น 404 | เมนูมีลิงก์ไป `/ai` แต่ไม่เคยมีหน้านี้ในโปรเจกต์ (backend มี API แล้ว แต่หน้าเว็บยังไม่ได้ทำ) | สร้างหน้า `/ai` จริง: ถ้าปิดใช้งานจะอธิบายวิธีเปิด, ถ้าเปิดแล้วแต่ต่อ gateway ไม่ได้จะเตือน, ถ้าใช้ได้จะถาม-ตอบพร้อมแสดงคำสั่งที่ใช้ |
| 2 | ช่องค้นหาสินค้ายังโชว์ผลของคำค้นก่อนหน้าระหว่างรอผลใหม่ ถ้ากดเร็วจะได้สินค้าผิดตัว (ในการทดสอบทำให้ใบแปลงหน่วยไปเข้าสินค้าที่ไม่เกี่ยวข้อง) | `ProductAutocomplete` เปลี่ยนรายการเมื่อผลลัพธ์กลับมาเท่านั้น และปิด filter ฝั่ง client ไว้ (ถูกต้องสำหรับการค้นแบบ async) จึงเหลือรายการเก่าให้กดได้ราว 250 มิลลิวินาที + เวลาเน็ต | เก็บคำค้นคู่กับผลลัพธ์ และไม่แสดงรายการถ้าคำค้นไม่ตรงกับที่พิมพ์อยู่ พร้อมเทสต์กันซ้ำ (เทสต์นี้ล้มเหลวถ้าถอดการแก้ออก) |
| 3 | ช่องจำนวน/ต้นทุนในใบรับสินค้าและใบปรับปรุงไม่มีชื่อกำกับ (screen reader อ่านไม่ได้) | เป็น `MoneyField` ในตารางที่ไม่ได้ส่ง `aria-label` | ใส่ชื่อกำกับตามคอลัมน์ + ชื่อสินค้า |
| 4 | กดปุ่มดาวน์โหลดไฟล์สำรองบน iPad แล้วไม่มีอะไรเกิดขึ้น (ผู้ใช้แจ้ง) | โค้ดเดิมดึงไฟล์ทั้งก้อน (~80 MB) มาเป็น Blob แล้วสร้าง `<a download>` กดเอง — iPadOS Safari ไม่รองรับ attribute `download`, การกดเกิดหลัง `await` จึงพ้นช่วง user gesture (เบราว์เซอร์บล็อก), object URL ถูก revoke ทันที และการเก็บ 80 MB ในหน่วยความจำก็ล้มได้เอง | ให้ API เซ็นลิงก์อายุ 5 นาที (HMAC ของ ร้าน+ชื่อไฟล์+เวลาหมดอายุ) แล้วให้เบราว์เซอร์ดาวน์โหลดเอง — ไม่ต้องคัดลอกลงหน่วยความจำ มีแถบความคืบหน้าจริง และดาวน์โหลดต่อได้ (รองรับ Range) พร้อมเทสต์ทั้งฝั่ง Go และเบราว์เซอร์ (จอ iPad) ที่ล้มเหลวถ้าถอดการแก้ออก |

ข้อสังเกตที่ไม่ใช่ข้อบกพร่อง

- URL สาธารณะผ่าน tunnel ช้ากว่าเข้าตรงประมาณ 0.9 วินาที/คำขอ (0.88s เทียบ 0.03s) ใช้งานได้ปกติแต่ถ้ารันชุดทดสอบให้ใช้ `BASE` ตรงเข้าเซิร์ฟเวอร์
- บิลขายเชื่อที่รับชำระไปแล้วบางส่วน **ยกเลิกไม่ได้** (ระบบกันไว้ตามที่ออกแบบ) ต้องรับชำระให้ครบหรือทำใบคืนสินค้า
- API ปฏิเสธฟิลด์ที่ไม่รู้จัก เช่น ส่ง `share_capital` ตอนสร้างสมาชิกจะได้ 400 (ชื่อฟิลด์จริงคือ `opening_share`) — เข้มงวดโดยเจตนา เพื่อไม่ให้ข้อมูลตกหล่นแบบเงียบๆ

### ผู้ช่วย AI

ทดสอบกับ gateway จริง `https://hybrid-llm-sp01.tdev2022.com` (โมเดล `T-LLM-GC`) — ถามจากหน้าเว็บ "วันนี้ขายได้กี่บิล" ได้คำตอบ "4 บิล" พร้อมคำสั่ง `SELECT` ที่ใช้ ใช้เวลารวมประมาณ 2-6 วินาที ชุดทดสอบตรวจด้วยว่าคำสั่งที่ระบบสร้างต้องไม่มี `INSERT/UPDATE/DELETE/DROP`

Gateway บน LAN (`192.168.1.116:9001`) ยังใช้ไม่ได้จาก tee-dev — ถูกบล็อกทุกพอร์ต (`No route to host`) ตั้งแต่ระดับเครือข่าย ก่อนถึง IP whitelist ของ gateway จึงต้องแก้บนเครื่องนั้นเอง (ดู `DEPLOY.md` ข้อ 7)

## ทดสอบหลายร้าน (multi-tenant)

```bash
cd frontend
ADMIN_PASS='<รหัสผ่านผู้ดูแลแพลตฟอร์ม>' node tests/live/multi-store.mjs
ADMIN_PASS='...' BASE=http://100.122.174.19:3010 node tests/live/multi-store.mjs   # เข้าตรง เร็วกว่า
```

สร้างร้าน `KAEN` ("ร้านค้าชุมชนบ้านแก่น") ผ่านหน้าผู้ดูแลแพลตฟอร์ม ถ้ามีอยู่แล้วจะใช้ร้านเดิมต่อ
(ถ้าต้องการเริ่มใหม่หมดให้ลบร้านออกก่อน: `delete from stores where code='KAEN';` — ข้อมูลลูกทั้งหมดถูกลบตาม cascade)
